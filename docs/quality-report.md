# SmartHabit quality hardening report

Date: 4 August 2026

## Scope

This pass reviewed the completed public FastAPI application and plain HTML/CSS/JavaScript frontend. It did not add authentication, change the saved model, retrain the model, or change prediction behavior.

## Findings and fixes

| Area | Finding | Fix or verified control |
|---|---|---|
| API input validation | Prediction inputs were already constrained by Pydantic, finite, required, category-limited, and configured to reject extra fields. | Retained the exact 12-field model contract. Validation error details now expose only `loc`, `msg`, and `type`; submitted values are not echoed. |
| CORS | Origins came from the environment, but wildcard or malformed configuration was not rejected and credentials were enabled unnecessarily. | `ALLOWED_ORIGINS` now requires one or more explicit HTTP(S) origins. Wildcards, paths, queries, fragments, and non-HTTP schemes fail at configuration load. Credentials are disabled and allowed headers are limited to `Accept` and `Content-Type`. |
| Request body size | There was no application-level request-size limit. | Added declared and streamed body enforcement with `MAX_REQUEST_BODY_BYTES` (default 16,384; accepted configuration range 1,024–1,048,576). Oversized requests receive a safe JSON `413` response. |
| Request correlation | Responses and logs did not have a correlation identifier. | Every HTTP response receives a server-generated UUID in `X-Request-ID`. The same value is recorded in structured access and error events, including framework-level `500` responses. Client-supplied IDs are not trusted. |
| Logging | Existing operational logs were not consistently structured. | Added JSON request logs containing only timestamp, level, event, request ID, method, path, status, and duration. Bodies, query strings, user values, and filesystem paths are excluded. Unexpected errors log only the exception type, not the exception message or stack trace. |
| Error safety | Public unexpected-error text was already generic, but Pydantic details could echo rejected input. | Sanitized validation details and retained the generic `500` envelope. Regression tests confirm a deliberately sensitive exception message and invalid input value are absent from responses. |
| Response headers | Security and privacy headers were missing. | Added `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, a restrictive `Permissions-Policy`, and `Cache-Control: no-store` for API responses. Production responses also receive HSTS. |
| Repository hygiene | `.gitignore` covered only `.env`, `.venv`, and `data/`; generated Python caches were committed. | Expanded exclusions for environment files, virtual environments, Python/test/lint caches, generated bytecode, raw Kaggle data, archives, logs, editor files, and temporary files. Removed tracked `__pycache__`/`.pyc` artifacts. |
| Secrets | A local `.env` exists but is ignored. | Verified `.env` is not tracked. A high-confidence scan of 84 tracked paths found no API keys, private keys, passwords, or client secrets. `.env.example` contains configuration examples only. |
| Accessibility | The application already used semantic landmarks, skip links, visible focus styling, accessible dynamic labels, descriptions, error regions, and reduced-motion support. | Verified all five HTML pages have `lang="en"`, one main landmark, headings, a skip link, and valid local links. Verified dynamic inputs receive labels and `aria-describedby`; inline errors use live regions. |
| Contrast | Key text/background pairs required confirmation. | Programmatic WCAG contrast checks passed: landing primary 13.75:1, landing secondary 10.38:1, content body 14.15:1, content secondary 5.26:1, and dashboard body 14.07:1. |

## API input controls

`PredictionRequest` remains the authoritative request contract. It:

- requires all model input fields;
- forbids unknown fields, including `id`;
- enforces observed numeric bounds;
- rejects NaN and positive/negative infinity;
- limits categorical values to fitted categories; and
- validates before DataFrame construction or model execution.

The schema, shared feature engineering, saved preprocessing pipeline, class mapping, and probability bounds remain unchanged.

## Accessibility review

The static and source-level audit covered:

- programmatic form labels and helper/error associations;
- keyboard-visible `:focus-visible` states;
- semantic `header`, `nav`, `main`, `section`, `aside`, and `footer` regions where appropriate;
- skip navigation;
- status, alert, progress-bar, and live-region semantics;
- responsive layouts at existing breakpoints;
- `prefers-reduced-motion` behavior; and
- representative foreground/background contrast ratios.

The in-application browser connection was unavailable in this execution environment, so the accessibility review used deterministic HTML, CSS, JavaScript, link, and contrast checks rather than a rendered browser session.

## Remaining limitations

- Response headers for frontend assets depend on the production static-file host. The FastAPI controls in this report apply to responses served by the API process.
- Browser and assistive-technology testing should still be repeated in the final deployment environment because static analysis cannot reproduce every browser/screen-reader combination.
- The local runtime reports non-strict Python, pandas, and NumPy differences from the recorded training environment, plus a missing recorded LightGBM training version. Existing loader safeguards still treat scikit-learn and joblib mismatches as unsafe startup errors. These compatibility warnings do not alter the security controls in this pass.
- Rate limiting is not implemented. Deployment-level rate limiting is recommended if the public service is exposed beyond a classroom or demonstration environment.
